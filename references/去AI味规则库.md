# 去 AI 味规则库（减法层汇总与仲裁）

> 本文件是 **author-voice-distill 的减法层接口**：不发明新检测器（禁止重复造轮子），只做三件事——**路由**（哪个 skill 管什么）、**汇总**（通用 AI 指纹分类学）、**仲裁**（减法层与 voice-profile 打架时听谁的）。
> 具体改写动作调用既有 skill 执行；本文件只规定调用顺序、豁免边界与验收口径。

## 一、生态路由表（谁管什么，什么时候调谁）

| 需求 | 调用 | 口径要点 |
|---|---|---|
| 中文成稿清理（31 条模式） | `humanizer-zh` | 模式清单是**检查线索不是词语黑名单**；优先级：信息守恒 > 用户范围 > 作者声音 > 具体表达问题 |
| 英文成稿清理（26 条模式） | `humanizer` | **有样本先读样本，样本覆盖规则**（含破折号率）；改完必查 §1/§2/§6/§8/§19 五个高存活痕迹 |
| 白名单式实测改写（中文，11 条） | `lieflat-less-ai-tone` | **只改清单内命中的**，未命中逐字保留，框架零改动；有风格文档时**风格文档压过规则** |
| 只诊断不改写 + 追问意图 | `dbs-ai-check` | 22 特征 + 误伤警告表 + 体裁识别；改写前先问清作者本来想达成什么 |
| 最小有效编辑 + 保个人声音（英） | `no-ai-slop` | 保词汇/节奏/粗粝/幽默/跑题；「可移植性测试」：能原样搬到别处的句子就是废话 |

| 事实密度与可核查性 | `rossmann-no-ai-slop` | 每个判断落到可核查事实；数字必须真实可溯源，否则删 |
| 分层深度修补（长文/书稿） | `de-AI-writing` | 四遍固定顺序：叙事→篇章→句式→词表；修补两阶段（先完整缺陷清单、逐条引原文短语，再逐条修） |
| 正面风格基因（怎么写「好」） | `good-writing` | style-dna：厚段/长句链/语体三层/事实先行——**加法层的字段模板来源** |

**调用纪律**：一次修补只走一条主路径（默认 `humanizer-zh` 或 `humanizer`），`dbs-ai-check` 作诊断辅助，`de-AI-writing` 仅在长文多层缺陷时启用。**不要把多份清单叠加成更长的黑名单**——叠加只会放大误伤。

## 二、通用 AI 指纹分类学（跨 skill 合并去重）

> 判据先行：**成簇且无语境功能 = 指纹；单次且承载节奏/立场/信息 = 作者声。**
> 强度分级：**一见即改**（强信号）／ **weak alone 需同伴佐证**（同段再有一条才动手）——单点不治罪。

### 篇章层（最像 AI 的不是词，是结构）

- **大纲测试**：首句连读能成摘要 = 提纲扩写，不是文章
- **段落同构 / 位置指纹**：等长段、每段同型收尾、三案例凑数、引语总在段尾、列举总三项
- **模板段**：「挑战/机遇/展望未来」式三段套；每段线性回答「发生→为什么→结果→意义」
- **段尾总结 / 鸡汤结尾**：「总之」「这提醒我们」「而这一切」式升华；伪深刻收尾句直接删，不重写成更好的比喻
- **指示定位壳**：「X 正卡在这条裂缝里」式收束，**禁止换词逃逸**（换成同构句式仍是壳）
- **标题复读首句 / 谈论上一稿**：「这一段是刚补充的」「was added to replace」——文本谈论文本本身
- **碎段与砖墙**：碎段比任何词汇都更像 AI；但句长参差本身**不是**改写理由（见 §三）

### 句式层

- **二分对照壳 / 翻案腔**：「不是 A，而是 B」「问题不在 X，在 Y」——低频是正常修辞（鲁迅李敖罗翔都用），**800 字内 >3 次才是指纹**
- **戏剧化揭露**：「扯下遮羞布」「真相是」；冒号揭晓式：「最妙的地方：它会自己学」
- **起跑式铺垫 / 与假想敌辩论**：「Let's dive in」「不要误会，我并不是……」
- **单句收尾与戏剧碎片**：「文件没了。消失了。」「That is the real win.」
- **关联词对堆叠**：一旦…就 / 只有…才 / 通过…来，>2 即堆叠
- **极值判断**：「最残酷的地方在于」>1 即堆叠
- **拟人化否定金句 / 拟人化喻体**：「算法不讲情面」「像一位智慧的导师」——写实际功能
- **假主语 / 缺施事**：「投诉变成了修复」「决策浮现了」——找人，让人做主语
- **段首零主语评论**（中文特有）：非首段无回指的评论式开头
- **名词化壳**：「完成了对……的……」「实现了……的提升」——恢复动词（原文无数据不许补数）

### 词表层

- **路标词**：值得注意的是 / 总体而言 / 本质上 / 归根结底（后接大一号命题 = 升维过拟合）
- **无出处权威 / 不可追溯引语**：专家认为 / 研究表明 / 荣誉清单背书——要么给出处，要么保留归因不裸奔
- **伪口语与伪坦率**：说白了 / 拆一拆 / 先说结论 / 我 promise
- **伪学术腔与政论词**：底层逻辑 / 闭环 / 抓手 / 口径 / 定调 / 话术
- **协作口吻**：接下来我们将 / 作为 AI / 本文将要探讨
- **拔高词与填充语**：赋能 / 深耕 / 彰显 / 不仅是 X 更是 Y；it's worth noting / at its core
- **限定词堆叠**：could potentially possibly；回避 is/are/has 的 serves as / boasts
- **同义词刻意替换**：准的词就重复用，重复不是错

### 标点排版层

- **揭晓式破折号**：「答案其实很简单——专注」→「答案是专注」；冒号提示语「一句话总结：」
- **粗体当装饰**、装饰性标题、emoji 标题、两句话就起小标题、序数词通篇编号小标题
- **顿号串三项以上密集罗列**、强凑三段式

### 翻译腔层（只认五种结构，不许凭语感扩权）

过长前置定语 / 「当……时」从句 / 前置话题壳（「对于……来说」）/ 句首路标（「然而/因此」移入句中）/ 「这意味着」式复述。
**被动句、名词化、长句本身是正常中文书面语，不许当翻译腔改掉。**

### 中文特有补充

层叠的「的」／「进行＋动词」（保留正在/完成/计划义）／被字句堆叠（不改归因强度）／四字词空泛排比／「随着……的发展」空背景开头／「总而言之，拭目以待」套话收尾。

## 三、误伤豁免表（硬约束，不是参考）

以下特征看着像 AI 味，实测站不住，**不能作为改写理由**。本表与 voice-profile 的「个人特征豁免表」同等效力：

| 不改的东西 | 依据 |
|---|---|
| 句长/段长不够参差 | 实测与人类无差别；**不许为制造节奏拆句拆段** |
| 句内同构排比、独立成段的比喻 | 人类用得不比 AI 少 |
| 正文问句、设问、问句小标题 | 正文问句人类远多于 AI |
| 被动句、名词化、长句本身 | 正常书面语 |
| 「首先…其次」正文连接词 | 与人类无差别（只管小标题编号） |
| 反复写全称、少用代词 | 人类比 AI 更常重复同一名词 |
| 单字虚词偏少 | 方向是补不是删，且补虚词无法验收 |
| 引文、标题、专名、讨论措辞本身 | 引用某说法 ≠ 作者在用该说法 |
| 信件称呼落款、2022-11-30 之前的文本 | 不是 AI 产物 |
| 体裁规定的形式 | 短视频文稿件件金句是**体裁要求**；学术/法律穷尽反驳是**规范**；公文不必强加「我/你」 |

**体裁识别先于判定**（`dbs-ai-check`）：短视频文稿 / 公众号长文 / 推文 / 学术文体，四套阈值不同。没问体裁就先自行判断，并在报告里注明判断结果。

**信息守恒**（`lieflat` / `shuorenhua` / `humanizer-zh` 三方一致）：

- 不许新增姓名/数字/日期/引语/来源/因果/心理活动——改写后每个实词都能在原文指出出处，指不出就是编造，撤销
- 不许删减限定词与让步（「可能」「据说」「通常」）——把「可能提升」改成「提升」是篡改，不是去 AI 味
- 「把抽象写具体」不是减法层的职责；缺数据就保持抽象，或问，不许造
- **保留作者声音清单**（humanizer）：奇特细节、未解决的矛盾情绪、年代梗、第一人称选择、括号自纠、真实的犹豫

## 四、仲裁案例：破折号（三方口径打架时怎么办）

| skill | 口径 |
|---|---|
| `humanizer` | 默认删；**样本里用破折号就按样本比率保留** |
| `humanizer-zh` | 功能性破折号可留，只清万能连接式 |
| `lieflat` | 只清揭晓式；实测部分模型几乎不用破折号，不构成痕迹 |

**裁决**：先查 voice-profile 的标点指纹。作者破折号频率在语料里是多少就保留多少，只清「揭晓式」这一种功能；语料没有作者数据时，按最严口径（只清揭晓式），并在档案标注「待采样验证」。**规则分歧永远让位给作者实测数据。**

## 五、仲裁规则（减法层 vs 加法层，五条）

1. **风格文档优先。** voice-profile.md 与任何减法规则冲突时，**以 voice-profile 为准**——那是目标作者的真实写法，不是 AI 痕迹。
2. **成簇 / 单次判据。** 作者特征 = 在语料里**反复核实**的习惯（文言虚词、厚段长句、括号冷笑、「罢了」式收束），进白名单；通用指纹 = 跨作者恒定的模板，一律清。
3. **禁止换词逃逸。** 命中壳式结构时，把固定词换成同义词不算修好；要么改成直陈句，要么按白名单保留原样并在档案注明。
4. **加法不得复辟。** 减法层刚清掉的对照壳/路标/段尾总结，**不许以「作者公式」名义加回**；签名动作每篇只选 3–5 个，不叠、不成簇——一旦变成固定栏目，它自己就长成新指纹。
5. **完美是另一种不真实。** 作者的毛边、卡顿、没想通的地方、跑题的括号是真实信号；减法层的职责是**去模板**，不是把文章磨光滑。修圆一切 = 制造第二种 AI 味。

## 六、应用配方（写作/修补的标准顺序）

    ① 加法定调   voice-profile 注入：选 3–5 个签名动作，字段写成「区间＋禁令＋正误对照例句」
    ② 减法清指纹 按 §二 检查，按 §三 豁免，按 §五 仲裁；只动命中的，未命中逐字保留
    ③ 兜底快查   只跑一次：大纲测试 / 高存活五痕迹（对照壳·收尾句·三段式·破折号·粗体）/ 信息守恒回滚
    ④ 验收       检测报告作证据 → 盲测作唯一判据

- **回滚检查**（`de-AI-writing`）：修完看段落是否变薄、长句链是否断裂、锋利判断是否被磨平。命中任一 → 退回重修。**减法减掉个人特征，比留着模板更糟。**
- **检测器只提供证据，不提供判决。** 检测报告、五维评分、命中清单都是「可核对的证据」；「像不像作者本人」的最终判据只有盲测（见 SKILL.md 阶段 4）。
- **追问优先于改写**（`dbs-ai-check`）：每个 AI 特征背后有作者本来想达成的目的。没搞清意图前不改一个字；改法必须用作者自己的方式达成同一目的。
- **修补两阶段**（`de-AI-writing`）：先出完整缺陷清单（逐条引原文短语、标编号与强度），再从最深层逐条修。先斩后奏的修补无法验收。
